# 개발 기록

OGs 액셀 역할 교체 패치의 리버스 엔지니어링과 빌드 파이프라인 기록입니다.
포맷 규명 내용, 사용한 기법, 시행착오에서 얻은 교훈을 정리했습니다.

## 출발점

PS2 OGs는 아카이브가 층층이 쌓여 있습니다. 역할을 바꾸려면 네 군데를 손봐야 했습니다.

| 대상 | 위치 | 내용 |
|---|---|---|
| 파일럿 신원 | `SHARED.BIN` `0x5DA000` · `IM.BIN` `0x83F000` | 이름 · 초상화 · 상태창 |
| 기체 | 같은 아카이브의 `Unit` 태그 | HP · 무장 · 기체 ID |
| 이벤트 대사 | `MAP.BIN` `0xC10800` | 시나리오 텍스트 |
| 전투 대사 · 음성 | `BATTLE.BIN` LICE 엔트리 5 | 대사 · 보이스 ID |

## 텍스트 시스템

### 한국어 코덱

OGs 한글패치는 Shift-JIS 자리에 **KS X 1001 완성형**을 오프셋 `+1410`으로 밀어 넣습니다.

- 한 글자 **2바이트**
- `@` = 줄바꿈 (**1바이트**)
- `　` = 전각 공백 (2바이트)

길이 계산에서 `@`가 1바이트라는 점이 중요합니다. 줄바꿈을 하나 넣으면 2바이트가 아니라
1바이트를 씁니다. 문장이 아슬아슬할 때 이걸로 한 글자를 벌 수 있습니다.

### MAP.BIN의 제약

대사 레코드는 **절대 오프셋으로 참조**됩니다. 포인터 테이블을 재배치할 수 없다는 뜻입니다.
레코드 뒤 NUL이 정확히 1개인지 169개를 실측해 확인했습니다 — **여유가 0바이트**입니다.

그래서 새 문장은 반드시 **원문 인코딩 길이 이하**여야 하고, 남는 자리는 NUL로 채웁니다.
`액셀`(2자)이 `라미아`(3자)보다 짧아 대부분은 여유가 생기지만, 반대 방향(적 쪽)은
빠듯해서 문장을 줄여야 했습니다.

## 신원 시스템 (PTbl / Plot)

| 태그 | 오프셋 | 비고 |
|---|---|---|
| `PTbl` | `0x13A478` | 파일럿 테이블 |
| `Plot` | `0x13B484` | 스트라이드 `0x94`, `+0x48`이 초상화 |

SHARED와 IM **양쪽에 같은 값을 써야** 합니다. 한쪽만 고치면 화면에 따라 다른 얼굴이 나옵니다.

## 유닛 마스터

`Unit` 태그가 `0x11F898`(아카이브 상대), 데이터가 `0x11F8A4`, 427 레코드 × 스트라이드 `0x64`.

| 필드 | 내용 |
|---|---|
| `+0x00` | HP |
| `+0x02` | 플래그 |
| `+0x0C` | internal id (안쥬르그 `0xD3` / 소울게인 `0x14A`) |
| `+0x24`~`+0x30` | 무장 ID |
| `+0x46` | 기체 uid (안쥬르그 `0x2B` / 소울게인 `0x63`) |

무장 ID 대역이 아군끼리(`0xD8x`/`0xD9x`) 적끼리(`0x8Bx`/`0xA5x`) 붙어 있어 편이 갈립니다.

### 배운 것 — 적 자리를 통째로 덮으면 안 된다

처음엔 레코드 전체를 복사했습니다. 그랬더니 HP 150,000짜리 보스가 6,200이 됐습니다.
적 보스 슬롯은 **HP와 플래그를 원래 값으로 남기고** 나머지만 교체해야 합니다.

### 배운 것 — 앙주르그는 사라지지 않았다

"게임에 안쥬르그가 더는 없다"고 판단하고 단방향 교환만 했습니다. 사용자 지적으로
다시 보니 안쥬르그 레코드가 3개 남아 있었고, 제가 그걸 전부 덮어쓴 상태였습니다.
기준 ISO에서 원본을 읽어 와 양방향으로 다시 구성했습니다.

**교훈**: "없다"는 결론은 전수 확인 없이 내리면 안 됩니다.

## 전투 대사 청크

`BATTLE.BIN` LICE 엔트리 5(`0x6062E800`)에 들어 있습니다.

청크 헤더는 `u16[16]`이고 `[12]`~`[15]`가 각각 f2 · f3 · f4 · 문자열 풀의 상대 오프셋입니다.
그 앞에 f1이 붙어 있어 `f1 = f2 - 2N`으로 구합니다.

| 배열 | 폭 | 내용 |
|---|---|---|
| `f1` | u16 | 문맥 ID (무기 ID 또는 상대 rawkey) |
| `f2` | u16 | `(플래그 & 0xF800) \| (rawkey & 0x7FF)` |
| `f3` | u16 | 풀 상대 오프셋 |
| `f4` | u32 | 음성 ID (`뱅크 * 1000 + 클립`) |

### 플래그 의미

원본 OGs 액셀 대사에서 역산했습니다.

| 값 | 상황 |
|---|---|
| `0x0000` | 경상 · 짧은 공격 |
| `0x0800` | 공격 |
| `0x1800` | 중상 · 위기 |
| `0x3800` | 회피 · 평가 |
| `0x4800` | 조준 · 명중 |
| `0x7000` | 필살 · 무기명 |

### 배운 것 — `f2 = 0`은 종단자다

기준 ISO를 보니 청크마다 `f2 = 0` 슬롯이 **맨 끝에 정확히 하나**뿐이었습니다.
빈 슬롯을 채울 때 마지막 하나는 반드시 0으로 남겨야 합니다.

### 배운 것 — 작은 ctx 값은 무기 ID가 아니다

`0x0100`·`0x0208`·`0x0441` 같은 값에는 레코드가 16~39개씩 달려 있습니다.
이건 무기 ID가 아니라 **범용 조건 코드**입니다. 무기 ID로 착각하고 ctx로 묶었더니
`가드가 열렸나！` 자리에 `포기하라구`가 들어갔습니다.

**레코드가 4개 이하인 희소 ctx만 무기로 판정**하도록 고쳤습니다.

## A PORTABLE에서 음성 가져오기

PSP **슈퍼로봇대전 A PORTABLE 한국어판**은 OGs와 같은 엔진 계열입니다.
LICE/Wpbb 아카이브, `PTbl`/`Plot`/`Unit`/`Weap`/`Sent` 태그, 전투대사 청크 구조,
그리고 **한국어 코덱까지 동일**합니다.

원본 아카이브는 일본어 그대로이고 한국어 패치는 `USRDIR/dummy.bin`에 따로 들어 있습니다.

| 청크 | 내용 | 줄 수 |
|---|---|---|
| `0xD4` | 아군 액셀 (기억상실) | 150 |
| `0xD5` | 각성 후 액셀 | 193 |

`0xD5`는 **OGs 액셀과 같은 스크립트**(번역만 다름)라 상황 판정의 기준이 됐습니다.
difflib으로 대응시켜 162개 고유 문장 중 68개를 확정할 수 있었습니다.

### 음성 파이프라인

```
A PORTABLE ATRAC3+ → ffmpeg → 32kHz 모노 PCM → PS2 VAG ADPCM → ILD → OGs 뱅크 1046
```

### 배운 것 — 용량 한계는 개수가 아니라 바이트다

디스크립터가 194개라 "194클립까지"라고 생각했습니다. 실제 한계는
**STRM 영역 바이트**(`0x88A800`)였습니다. 189클립에서 이미 8,624,128바이트,
192클립에서 8,996,864바이트로 8,955,904를 넘겼습니다.

추정식이 실제 인코딩보다 4%쯤 작게 나오므로 예산에 여유를 둡니다.

## 대사 배치

여기서 사고가 제일 많이 났습니다. 전부 **실기에서** 발견됐습니다.

### 사고 1 — 피격에 「코드 기린 풀 드라이브」

원인이 셋 겹쳐 있었습니다.

1. 무기명 대사가 `fin` 풀에 무기 우선 정렬로 들어가 일반 대사 자리로 샜다
2. 클립을 줄일 때 `pool.get(cat) or pool['atk']`로 떨어뜨려 대체 순서를 무시했다
   (`crisis`가 `atk`로 떨어짐)
3. `기린！ 진・극！！`이 무기명 판정에 걸리지 않았다

### 사고 2 — 현무강탄에 「범위 밖인가」

`되는 대로 밖에 안 되나`(ctx `0x04B5`, 현무강탄 계열)를 `miss`로 분류했습니다.
A PORTABLE의 같은 대사 「될 대로 되는 수밖에 없나」는 **공격 구간**에 있습니다.

키워드 규칙을 버리고 **A PORTABLE 대응을 1차 분류기**로 삼았습니다.

### 사고 3 — 짝 대사를 잃어버림

「로케트・소울 펀치！ 막 이래！」는 단독 대사가 아니라 **현무강탄 세트의 둘째 줄**입니다.
무기명 대사를 고를 때 **다음 인덱스를 짝으로 함께** 가져오도록 고쳤습니다.

### 사고 4 — 재사용 우선이 무기명을 밀어냈다

바이트를 아끼려고 이미 패킹된 클립을 우선 고르게 했더니, `이게、풍인섬이다` 자리에
`꺼져라。이 세계에서`가 들어갔습니다. **무기명 풀에는 재사용 우선을 적용하지 않도록** 분리했습니다.

## 대사 교체에서 겪은 것

규칙 기반 일괄 치환은 반드시 사고를 냅니다. 실제로 잡아낸 것들입니다.

| 사고 | 원인 |
|---|---|
| `액셀렌` → `라미아렌` | 엑셀렌의 이표기. `액셀` 접두 일치 |
| `액셀레이션` → `라미아레이션` | 슬레이의 필살기명 |
| `액셀이란` → `라미아가란` | 조사 규칙 순서 (`이` 가 `이란` 보다 먼저) |
| `무장해제 해라` → `무장해내 해라` | `제　`→`내　` 규칙이 어중을 때림 |
| `고맙습니다` → `고맙어` | 반말 변환 규칙의 과적용 |
| `일어나는` → `일어난` | `나는`→`난` 규칙에 단어 경계가 없음 |
| `이게 전쟁이야` → `전쟁이야` | `이게` 일괄 제거 |

`지 않` → `잖` 규칙은 부정을 뒤집어 버려 아예 삭제했습니다.

### 배운 것 — 어미만 봐선 안 된다

존댓말을 지우는 작업을 여러 차례 반복했는데, 쓸어도 쓸어도 남았습니다.

`-ㅂ니다`(37) → `님` 호칭(52) → `…네。`(17) → `어요/드릴/셨/가요`(7) →
`않으셔도/말씀하신거지/말씀인가`(4) → `레몬…님？`(말줄임표로 끊긴 형태)

어미만 보면 호칭과 대답어가 남습니다.

### 배운 것 — 표본 검사로는 못 잡는다

기계적 규칙 + 표본 검사로 진행하다 사용자에게 지적받고 **대화 단위 정독**으로 바꿨습니다.
그 즉시 `라이마`·`라마아`·`소율게인`·`러블리스`·`라미라미` 같은 오탈자가 쏟아졌습니다.

장면이 아니라 **대화 단위**로 끊어 읽어야 합니다. 화자 태그로 걸러내면
`엑셀렌：…쭉쭉～빵빵이라고` 같은 무표시 줄을 놓칩니다.

### 배운 것 — 캐릭터 설정을 지우지 말 것

액셀의 W 넘버 정체성을 6줄 지웠다가 되돌렸습니다. 111줄이 그를 W 시리즈로 부릅니다.
엑셀렌의 `엑세 누님` 개그도 25줄을 건드렸다가 복원했습니다.
본인이 "『엑세누님』이라고 부를 것。그게 룰이야？"라고 못박아 둔 설정입니다.

## 검증

정적 검증은 다음을 확인합니다.

- 원문 인코딩 길이가 기록된 길이와 일치
- 현재 바이트가 기대값과 일치, 다음 바이트가 NUL
- 새 문장 길이가 원문 이하
- 괄호 균형 (닫는 괄호가 잘려 나가는 사고가 있었습니다)
- 무기명 대사와 슬롯 무기의 일치

xdelta는 만든 뒤 반드시 되돌려 검증합니다.

```bash
xdelta -d -c -f -s base.iso patch.xdelta | sha256sum
```

`-c`(stdout) 없이 `-`만 쓰면 검증이 되지 않습니다.

**다만 정적 검증으로 잡히지 않는 것이 있습니다.** 위에 적은 대사 사고 네 건은
전부 실기에서 발견됐습니다. 인게임 확인을 대체할 방법은 없습니다.
